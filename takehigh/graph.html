① グラフとは何か

グラフは、頂点と、それらをつなぐ辺からなるデータ構造です。人のつながりや論文の引用関係など、さまざまな関係を表現でき、幅広い分野で使われています。

この教材で使うグラフを作ってみましょう。あらかじめ用意されたグラフを使うこともできます。まず有向・無向を選び、次に頂点数を決め、最後に頂点どうしをつなぐ辺を編集してください。

② 逐次実行モデル：頂点を1つずつ順番に探索・処理する

逐次実行モデルでは、1つの実行主体がグラフの頂点を順番にたどり、到達した頂点で処理を実行します。

ここでは、どの順番で頂点をたどるか（探索方法）と、頂点で何をするか（Compute）を分けて考えましょう。

探索には深さ優先探索（DFS）の順序を使います。迷路で右手を壁に沿わせながら進む「右手法」のように、1人の探索者が道を進み、行き止まりでは引き返して別の道を調べます。

今回は、開始頂点から各頂点までの最短距離（SSSP）を求めます。辺の長さはすべて1です。より短い経路が見つかったら、その頂点の距離を更新して探索を続けます。

発展：逐次実行モデルのコードと探索方法

頂点で実行するComputeは共通です。探索依頼を処理する順序を切り替えます。方式を変更すると②の実行を最初からやり直します。

function dfs(vertex, input) {
  const outputs = [];

  compute(input, {
    getValue() { return vertex.value; },
    setValue(v) { vertex.value = v; },
    exploreNeighbors(v) {
      for (const to of vertex.neighbors) {
        outputs.push({ to, value: v });
      }
    }
  });

  for (const message of outputs) {
    dfs(message.to, message.value);
  }
}

③ 並列実行モデル：複数の頂点を同時に処理する

並列実行モデルでは、複数の実行主体が、それぞれ異なる頂点を同時に処理します。

ここでは、並列グラフ処理の仕組みであるPregelを紹介します。Pregelでは、Activeな頂点がComputeを実行し、必要に応じてほかの頂点へメッセージを送ります。処理はSuperstepと呼ばれる単位で進み、送信されたメッセージは次のSuperstepで届きます。

頂点の実行状態

頂点には、処理を実行するActive（活性）と、処理を停止しているHalted（停止）の2つの状態があります。

voteToHalt()を呼ぶと処理終了後にHaltedになりますが、メッセージを受信すると再びActiveになります。呼ばなければ次のSuperstepでもActiveのままです。

Superstepの流れ

活性停止 →メッセージ HvoteToHalt()

左の図は、3つの頂点が4つのSuperstep（SS0〜SS3）で処理を進める様子を表しています。

SS0では頂点1のみがActiveで、頂点2と3はHaltedです。複数の頂点にメッセージを送ることができ、ここでは頂点1が頂点2と3の両方に送信します。

SS1ではメッセージを受信した頂点2と3がActiveになります。Haltしなかった頂点1も処理を続けます。

SS2では受信した頂点1と3がActiveになり、Haltしなかった頂点2も処理を続けます。SS3では頂点2が受信によって再びActiveになります。

図のHはvoteToHalt()の呼び出しを表します。すべての頂点がHaltedになり、未配送のメッセージもなくなると、計算が終了します。

Pregel実行モデルのコードを見る

実行モデルの概念を示す擬似コードです。SS0では全頂点がActiveで、送信したメッセージは次のSuperstepで届きます。実際の⑤は頂点を順に処理する教材用シミュレータです。

let inbox = emptyInbox();

for (let ss = 0; ss < MAX_SUPERSTEPS; ss++) {
  const outbox = [];

  for (const vertex of vertices) {
    const inputs = inbox[vertex.id];
    if (!vertex.active && inputs.length === 0) continue;
    vertex.active = true;

    const api = {
      superstep: ss,
      id: vertex.id,
      vertexCount: vertices.length,
      outDegree: vertex.outNeighbors.length,
      params,
      outNeighbors() { return [...vertex.outNeighbors]; },
      getValue() { return vertex.value; },
      setValue(v) { vertex.value = v; },
      send(to, v) { outbox.push({ from: vertex.id, to, value: v }); },
      sendToNeighbors(v) {
        for (const to of vertex.outNeighbors) this.send(to, v);
      },
      voteToHalt() { vertex.active = false; }
    };

    compute(inputs, api);
  }

  if (vertices.every(v => !v.active) && outbox.length === 0)
    break;
  inbox = deliver(outbox);
}

emptyInbox・deliverなどは説明用の処理です。頂点への配送と終了判定は実行モデルが担当します。

① グラフ作成で頂点・辺・初期valueを設定し、⑤ PlaygroundでComputeを編集して実行します。コードを確定し、行送り・SS送りで途中の状態を確認し、最後のvalueが課題の条件を満たすか確かめましょう。SSSPやCCのコードを出発点として利用できます。

課題1　2頂点間の到達可能性（Reachability）

有向グラフで、指定した頂点Aから目的頂点Bへ到達できる経路が存在するかを判定するComputeを書いてください。AとBは異なる頂点です。すべての頂点の到達可能性を求める必要はありません。

初期value
開始頂点Aは1、目的頂点Bは2、それ以外は0。AとBはそれぞれ1つだけ指定します。
目標
計算終了時、Bのvalueが3なら到達可能、2のままなら到達不可能です。途中の頂点は情報を受け取ったことを1で記録できます。Bに情報が届いたら、Bから先に伝える必要はありません。
ヒント
Aから辺の向きに沿って情報を伝えます。初めて情報を受け取った途中の頂点だけが次に伝え、Bで受け取ったことを記録します。サイクルがあっても同じ情報を送り続けないようにしましょう。api.voteToHalt() は現在の頂点だけを停止するため、Bに到達しても他の頂点の処理は自然に終了するまで続きます。
試してみよう
Aを頂点1、Bを頂点3にして、1→2→3、3→4、4→2という有向グラフを作ります。Bには到達可能ですが、Bで伝播を止めれば4のvalueは0のままです。2→3の向きを逆にして、到達不可能になることも確かめましょう。

課題2　2地点からの共通到達可能性

頂点1が情報A、頂点2が情報Bを発信します。有向グラフで両方の情報が届く頂点を見つけるComputeを書いてください。

初期value
頂点1は1、頂点2は2、それ以外は0。
目標
0＝未到達、1＝Aのみ、2＝Bのみ、3＝両方。最終valueが3の頂点が答えです。
ヒント
新しく受信した情報と、以前に受け取った情報を統合します。JavaScriptのビット論理和 | では、1 | 2 は3、1 | 1 は1になります。単純な足し算では同じ情報が重複します。
試してみよう
1→3、2→3、3→4、2→5のグラフで、3・4は両方、5はBのみになります。AとBが異なるSuperstepで届くグラフでも試しましょう。

課題3　三角形の検出

無向グラフで、自分の隣接頂点のうち、互いにも隣接している2頂点が存在するか調べるComputeを書いてください。3頂点すべてが互いに接続する三角形に所属する頂点を検出します。

初期value
すべての頂点を0にする。
目標
三角形に1つ以上所属する頂点は1、それ以外は0。三角形の個数を数える必要はありません。
ヒント
api.outNeighbors() で隣接頂点のID一覧を取得できます。隣接頂点同士でこの情報を交換してみましょう。api.sendToNeighbors(api.outNeighbors()) のように数値配列をそのまま送ることができます。自分の隣接頂点一覧と、ある隣接頂点から届いた隣接頂点一覧の両方に含まれる頂点を探してください。例えば、自分Aの隣接頂点がB・Cで、Bから届いた一覧がA・Cなら、A―B・A―C・B―Cの3辺が存在します。配列に値が含まれるかは 配列.includes(値) で確認できます。
試してみよう
1―2、2―3、3―1、3―4のグラフでは1・2・3だけが三角形に所属します。三角形のないグラフや孤立頂点も試しましょう。
